# Aftertaste — фронтенд

Прототип личного каталога на Vue 3 + TypeScript. Бэкенд пока не нужен.

## Запуск

Из корня проекта:

```sh
nvm use
cd frontend
npm install
npm run dev
```

`npm run build` проверяет TypeScript и собирает production-версию.

## Архитектура

Собственная модульная архитектура с идеями FSD. Полные правила:
[ARCHITECTURE.md](../docs/ARCHITECTURE.md).

- `src/app/main.ts`, `App.vue` — запуск и сборка приложения.
- `src/app/layout/` — AppLayout, AppHeader и AppFooter.
- `src/stores/index.ts` — Pinia; будущие сторы группируем по назначению в `stores`.
- `src/pages/catalog/CatalogPage.vue` — экран каталога.
- `src/pages/catalog/components/` — список, формы и модалки каталога; сохранён неиспользуемый CatalogCollage.
- `src/pages/catalog/composables/useCatalog.ts` — состояние и сценарии страницы.
- `src/entities/entry/model/entry.ts` — типы и категории записи; `ui/` — карточка и обложка.
- `src/api/catalog.ts` — функции чтения и сохранения, пока через localStorage.
- `src/mocks/demoEntries.ts` — демонстрационные записи.
- `src/shared/ui/` — `buttons`, `form`, `modals`.
- `src/shared/lib/date/` — обычные функции работы с месяцем.
- `src/shared/composables/` — место будущих общих технических composables; создаём с первым файлом.
- `src/styles/` — SCSS: `layout`, `catalog`, `ui`, глобальный `main.scss`, переменные и миксины.

Управление модалками остаётся прежним. Стор модалок и HTTP-интерцептор отложены.

## Данные и будущий API

При первом открытии показываются демонстрационные записи. После первого сохранения весь каталог хранится в этом браузере под ключом `aftertaste.entries.v1`. Это не аккаунт и не синхронизация между устройствами. Фото пока хранится как data URL; при переполнении localStorage появляется ошибка, форма остаётся заполненной.

`EntryDraft`: `type`, `title`, `rating`, `review`, `month` (строка `YYYY-MM`), необязательный `photo`. У сохранённого `Entry` также есть `id`. Рецензия необязательна; дата относится к прочтению, просмотру или посещению.

Для музыкальных альбомов (`album`) исполнитель (`artist`) обязателен. Название
альбома хранится в `title`; оценка, рецензия, месяц прослушивания и фото используют
общие поля записи. Исполнитель виден в карточке и просмотре. При смене типа
на другой исполнитель не сохраняется. Альбом без фото использует виниловую обложку.

«Выставки и музеи» (`exhibition`) — единый тип записи. Использует
название выставки/музея, оценку, необязательную рецензию, месяц посещения и фото.
Доступны в форме и фильтрах, сохраняются и редактируются как остальные записи.

Для спектаклей форма дополнительно показывает необязательные `theatreGenre`
(театр, опера, балет, мюзикл, другое) и `venue` (название театра или площадки).
Они сохраняются и отображаются в просмотре записи. При сохранении другого типа
эти поля очищаются. Старые записи без новых полей продолжают загружаться.

Для подключения бэка начни с `src/api/catalog.ts`: замени локальное хранение API-запросами. В `src/pages/catalog/composables/useCatalog.ts` нужно будет ожидать загрузку/сохранение, добавить состояние ожидания и отдельные операции создания и обновления. Загрузку фото можно заменить на multipart и хранить URL в записи. Визуальные компоненты останутся теми же.

## Что проверить вручную

1. Добавить запись каждого типа, выбрать оценку и месяц: запись появляется в нужной группе.
2. Открыть запись и отредактировать её; отмена не должна сохранять изменения.
3. Перезагрузить страницу: сохранённые записи остаются.
4. Проверить поиск, фильтры и пустые результаты.
5. Прикрепить фото, заменить и убрать; файл больше 2 МБ должен показать ошибку.
6. Проверить модалки с клавиатуры (Tab, Escape) и экран на ширине 375 px.
7. Для проверки ошибки сохранения временно выбросить `throw new Error('Test')` в начале `saveEntries`: уведомление об ошибке должно появиться поверх заполненной формы. После проверки убрать эту строку.
8. Для спектакля выбрать жанр и место, сохранить, перезагрузить и открыть просмотр/редактирование. Проверить старую запись без этих полей и смену типа на книгу: театральные поля не должны сохраняться у книги.
9. Добавить альбом с исполнителем, названием, оценкой и рецензией; перезагрузить, отфильтровать альбомы, открыть и отредактировать. Проверить пустого исполнителя и очистку исполнителя после смены типа на книгу.

## Соглашения Vue и SCSS

Порядок блоков: `template` → `script setup lang="ts"` → `style scoped lang="scss"`.
Все стили лежат отдельно от компонентов в `src/styles/`, с подпапками `ui`, `catalog` и `layout`. Имя SCSS-файла соответствует компоненту в kebab-case: `BaseButton.vue` → `base-button.scss`. Подключаем через алиас `@`:

```vue
<style scoped lang="scss" src="@/styles/ui/base-button.scss"></style>
```

Общие значения и миксины подключаем явно:

```scss
@use '@/styles/variables' as *;
@use '@/styles/mixins' as *;

.button {
  background: $color-accent;
  font-family: $font-body;
}

@include respond-below('tablet') {
  .button {
    width: 100%;
  }
}
```

Брейкпоинты: `wide` 1920, `desktop` 1440, `laptop` 1024, `tablet` 768, `mobile` 480 px. `respond-below` включает указанную ширину, `respond-above` — строго больше неё. Четыре колонки каталога появляются выше 1440 px, три — выше 1024, две — выше 480, одна — на 480 и меньше.

Шрифты: [Prata](https://fonts.google.com/specimen/Prata) для выразительных книжных заголовков и [Onest](https://github.com/google/fonts/blob/main/ofl/onest/METADATA.pb) для интерфейса. Оба поддерживают кириллицу и распространяются под SIL OFL. Подключены через Google Fonts в `index.html` с `display=swap`; без сети используются Georgia и Arial. Семейства можно заменить в `_variables.scss`.

Постоянные договорённости для следующих сессий сохранены в корневом `AGENTS.md`.

## Контейнер страницы

Шапка и основной контент используют `@include container`: `width: 90%`, `max-width: 1700px`, `margin-inline: auto`. Значения заданы в `_variables.scss`, миксин — в `_mixins.scss`. Дополнительных горизонтальных padding у контейнера нет.

Брейкпоинты зафиксированы: 1920 / 1440 / 1024 / 768 / 480 px. Контейнер плавно меняет ширину между ними.
