# Соглашения проекта Aftertaste

- Последнее утверждённое исключение для крайних оценок: 10 — винная карточка/подпись, белый текст, крупная оценка и наклонённая наклейка ❤️; 1 — светло-сиреневый #EEE8F2, графит #454549, крупная оценка и наклейка 💩. Без текста на плашках и без «На повтор»/«Без повтора» в карточках. Эти наклейки разрешены вопреки прежним ограничениям сдержанного стиля. При выставлении 10 — оборот с двумя дорожками и «Это — на повтор.», при 1 — остановка и «Одного раза хватило.». Анимация при выборе, с учётом prefers-reduced-motion.

- Утверждён стиль заглушек по `frontend/public/category-covers/book-abstract-v3.png`: крупный узнаваемый предмет с абстрактной геометрией, дугами как дорожки винила и лёгкой бумажной фактурой. Палитра: чёрный #1D1D1F, графит #454549, мягкий оливковый #A0A37B, винный #7D2826, светлый фон #F2EEDF. Предмет занимает почти всю картинку, хорошо читается в миниатюре; без текста и фотореализма. Книга v3 одобрена. Для фильмов — катушка киноплёнки, для сериалов — кинохлопушка, для спектаклей — театральные маски, для выставок и музеев — абстрактная картина в раме. Винил используется только для музыкальных альбомов. На десктопе область изображения карточки имеет aspect-ratio 3 / 2, мобильные миниатюры сохраняют прежние размеры. При новых генерациях использовать книгу как визуальный референс; предыдущие варианты сохранять отдельными файлами.

Эти договорённости отражают предпочтения пользователя. Применяй их при дальнейшей работе с фронтендом.

## Vue

- Vue 3, Composition API, TypeScript.
- Валидация форм — Vuelidate; первая проверка и показ ошибок — только после попытки отправить форму, не по фокусу или blur. После попытки отправки ошибки обновляются при исправлении полей. Правила остаются в форме, UI-поля получают текст через `error`. Ошибку показывать красным текстом с абсолютным позиционированием под контролом, резервируя место под текст; рамка и фон поля при ошибке — мягкие красные. Сохранять доступность через `aria-invalid` и `aria-describedby`.
- Типы в `defineProps` и `defineEmits` оформлять в несколько строк: каждое свойство или событие — на отдельной строке, даже если оно одно. Не сжимать объявления в строку с разделителями `;`.
- Поиск по справочникам, преобразования данных и сложную логику отображения выносить из шаблона в `<script setup>`, для производных реактивных значений использовать `computed`. В шаблоне оставлять привязки готовых значений и простые директивы отображения.
- Порядок блоков в каждом `.vue`: сначала `<template>`, затем `<script setup lang="ts">`, затем `<style>`.
- Делить интерфейс на понятные компоненты. Кнопки, поля ввода, модалки и уведомления — переиспользуемые UI-компоненты.
- Оставлять код понятным для пользователя, который учится и самостоятельно продолжает фронтенд.

## Стили

- SCSS организуем по компонентам: базовые стили, состояния и адаптив одного элемента держим в одном блоке селектора. `@include respond-below(...)`, `respond-above(...)` и локальные `@media` размещаем внутри этого блока, а не в отдельных секциях с повторением классов внизу файла.
- Дочерние элементы группируем внутри блока компонента, например `.entry-card { .entry-photo { ... } }`. Сохраняем понятные полные имена классов, избегаем чрезмерной вложенности (обычно 2–3 уровня). Для состояний используем `&`. Вложенность должна соответствовать реальному DOM: телепортированные меню и модалки оформляем отдельными корневыми блоками, дочерние Vue-компоненты — через `:deep()` там, где это необходимо. Общие reset и настройки библиотек остаются в глобальных стилях.

- Высота однострочных полей — 44px на десктопе, 40px на ширине до 768px и 38px до 480px. Плавающие подписи и иконки адаптируются к высоте. `BaseSelect` использует кастомный выпадающий список с клавиатурной навигацией, а не нативное меню `select`.
- Для даты записи используем `DatePicker` как обёртку над `@vuepic/vue-datepicker`: календарь дней без времени, значение `YYYY-MM-DD`. Для книг и сериалов передаём `range`, для остальных типов выбираем одну дату. В записи `date` хранит дату окончания, `dateStart` — начало периода, `month` — месяц окончания для группировки. Старые записи без дня сохраняют только месяц. Собственный календарь не реализуем: настраиваем цвета библиотеки. Меню календаря и селекта открываются поверх контента, не увеличивают прокрутку модалки и автоматически открываются вверх при нехватке места снизу. Полосы прокрутки оформляем глобально в `main.scss`, цвета — через переменные; сохраняем системную прокрутку и доступность.

- У `BaseInput`, `BaseTextarea` и `BaseSelect` плавающая подпись: внутри пустого поля, сверху уменьшенная при фокусе или заполненном значении. У нативных полей даты/времени подпись всегда поднята, чтобы не перекрывать маску. Фокус — мягкая рамка и лёгкий ореол; состояние ошибки сохраняет красный акцент.

- Использовать SCSS. Все стили хранить отдельно от Vue-компонентов в `frontend/src/styles/`. Стили UI-компонентов — в `styles/ui/`, каталога — в `styles/catalog/`, корневого компонента — в `styles/app.scss`. Имена SCSS-файлов — в kebab-case, строчными буквами: `EntryCard.vue` → `entry-card.scss`. Подключать через `<style scoped lang="scss" src="@/styles/ui/component-name.scss"></style>`. Не размещать SCSS рядом с `.vue`.
- Глобальные стили и reset — только в `frontend/src/styles/main.scss`.
- Основные цвета и семейства шрифтов — в `frontend/src/styles/_variables.scss`. Использовать семантические переменные вместо повторяющихся значений.
- Общие миксины — в `frontend/src/styles/_mixins.scss`: поля, действия модалок и адаптивность. Подключать через `@use`, не использовать устаревший Sass `@import`.
- Общий контейнер страницы: ширина `90%`, максимум `1700px`, по центру. Использовать `@include container` из `_mixins.scss`; значения `$container-width` и `$container-max-width` в `_variables.scss`. Не добавлять боковые padding к контейнеру, уменьшающие полезную ширину. Правило едино для шапки и основного контента на всех экранах.
- Брейкпоинты: wide — 1920px, desktop — 1440px, laptop — 1024px, tablet — 768px, mobile — 480px.
- `respond-below(name)` включает верхнюю границу (`max-width`), `respond-above(name)` использует строго большую ширину. Не вводить произвольные брейкпоинты без необходимости.
- Стили компонента не должны случайно затрагивать соседние компоненты. Для осознанного оформления дочернего компонента использовать `:deep()`.

## Шрифты

- Пользователю нравятся необычные, выразительные шрифты.
- Выбирать бесплатные шрифты с кириллицей и разрешённым использованием в вебе.
- Утверждённая пара: Prata для заголовков, Onest для основного текста и UI; обе под SIL OFL.
- Семейства меняются через `$font-display` и `$font-body`. Подключение Google Fonts — в `frontend/index.html`, с системными fallback-шрифтами и `display=swap`.

## Цвета и тон интерфейса

- Актуальное направление по референсам пользователя: винтажная журнальная эстетика, личный альбом, наклонённые карточки и крупные заголовки с засечками. Эта договорённость заменяет прежний бело-жёлтый графичный вариант.
- Палитра: бордовый `#7D2826`, сливочный `#EFE9D7`, оливковый `#898861`, глубокий зелёный `#343723`. Бордовый — действия и оценки, сливочный — основной фон. Не возвращать ярко-жёлтый без запроса.
- Literata для выразительных заголовков и курсива, Onest для интерфейса. Тонкие рамки и мягкие тени вместо тяжёлых смещённых теней. Сохранять небольшие наклоны акцентов.
- Обложки без фото используют общую бордово-оливковую палитру и геометрию, а не отдельные пастельные цвета категорий. Пользовательские фото сохраняются.
- Тон — дружелюбный, разговорный, на «ты», без нарочитого сленга и излишней поэтичности. Действия и ошибки должны оставаться понятными.
- Заголовок главной: «Сколько по десятибалльной?».
- Сохранять формулировку футера: «Можно не соглашаться с критиками».

- Уточнение направления: более минималистичный, сдержанный вид с намёком на искусство и коллекционные издания. Больше воздуха, мягкие скругления, меньше плашек. Пользователь любит винил: использовать пластинку и конверт как акцент первого экрана, не превращать каталог в музыкальный сервис.

- Актуальная итерация каталога: минималистичный список записей, небольшой заголовок, Onest без декоративных засечек на основном экране. Без искусственных обложек, дублирования названий, большого hero и коллажа. Фото показывать только при наличии. Винил — маленький знак у логотипа. Бордовый — основное действие, оливковый — детали, светлая основа. Это заменяет прежние требования к обложкам и крупной декоративной композиции; модалки пока остаются в предыдущем оформлении.

На основном экране использовать чисто белый фон, графитовый текст, нейтральные серые линии и бордовый акцент. Не считать текущую композицию списка одобренной — пользователь недоволен результатом.

## Архитектура фронтенда

- Используем собственную модульную архитектуру с идеями FSD, а не строгое следование FSD. Это заменяет прежние правила о сторах в model и сегментах ui/model страниц. Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Все сторы — в `frontend/src/stores`, с группировкой `catalog`, `auth`, `modals` по мере реализации. `stores/index.ts` создаёт Pinia. В стор выносим только необходимое общее состояние, не все переменные и не всю логику.
- Страницы: `pages/<страница>/<Имя>Page.vue`, локальные компоненты — в `components`, локальные composables — в `composables`. Другие страницы не импортируют их внутренности.
- Общие технические composables — в `shared/composables`, обычные утилиты — в `shared/lib`. Предметную логику не переносим в shared лишь потому, что она используется несколько раз.
- Общий UI группируем в `shared/ui/modals`, `shared/ui/form`, `shared/ui/buttons`. Формы записи остаются в каталоге. Оболочка, шапка и футер — в `app/layout`.
- Функции доступа к данным — в корневом `api`, например `api/catalog.ts`, в будущем `api/auth.ts`. API не импортирует сторы и UI, возвращает данные или выбрасывает ошибку. Если состоянием владеет стор, его действие выполняет запрос и обновление состояния.
- Сейчас `api/catalog.ts` использует localStorage. HTTP-клиент и интерцептор отложены до появления бэкенд-запросов. Перевод модалок на стор — отдельная будущая итерация; пока сохраняем существующее управление.
- `entities/entry` хранит типы, категории и отображение записи; не зависит от страниц, сторов и API. Shared не зависит от предметных модулей. Избегаем циклических импортов.
- Внешние импорты модулей с публичным `index.ts` идут через него; внутри используем абсолютные пути через алиас `@/`, без обращения к собственному публичному `index.ts`. Отдельный `.ts` каждому компоненту не нужен: props, emits и локальная логика остаются в script setup. Пустые папки и файлы заранее не создаём.
- SCSS остаётся в `frontend/src/styles`: оболочка — `layout`, каталог — `catalog`, общий UI — `ui`. Это дополняет прежние правила стилей. Стили корневого компонента при необходимости — `app.scss`, страницы — `catalog/catalog-page.scss`.

- Временные мок-данные и демонстрационные записи храним отдельно в `frontend/src/mocks/`, не в `api`. При подключении реального источника данных убираем соответствующие моки и их подключения.

## Учебные конспекты

- Когда пользователь уточняет теорию по TypeScript, Vue, фронтенду, бэкенду или другим технологиям, дополнять тематический конспект в `learning/`: краткая сводка, небольшие примеры и возможные вопросы для собеседования с ответами. Не копировать диалог; объединять повторяющиеся темы и сохранять техническую точность. Объяснение в чате также давать, не заменять его ссылкой на файл.
- Конспекты разделять по темам, имена файлов — в kebab-case: `typescript.md`, `vue.md`, `http.md`, `nestjs.md` и т. п. Новые файлы создавать только при появлении материала и добавлять в оглавление `learning/README.md`. Документацию самого проекта оставлять в `docs/`.

- BaseButton (2026-10-27): световой блик и подпрыгивание отменены. Пока только базовая смена цвета, без движения кнопки и появления тени; новый ховер отложен. Панель примерки удалена. Фон невыбранных rating-option — #A0A37B с прозрачностью 18%, без тени при наведении.

- На ширине 480px и ниже все модалки через BaseModal отображаются как выезжающая снизу панель с размытым фоном. Закрытие свайпом вниз за верхнюю полоску. Заголовок прокручивается вместе с содержимым; кнопки в слоте actions закреплены внизу панели. Учитывать safe-area и prefers-reduced-motion. Выше 480px — обычная модалка. Во всех модалках на ширине до 480px включительно кнопки действий стоят друг под другом и занимают всю доступную ширину с сохранением боковых отступов панели. Это общий паттерн проекта: использовать слот actions и миксин modal-actions, не дублировать правила в отдельных модалках.

- Крестик закрытия модалок скрыт до 480px включительно; выше — компактный IconButton. Закрытие формы с несохранёнными изменениями (включая фото и даты) требует подтверждения при отмене, Escape, клике по фону и свайпе. Неизменённая форма закрывается сразу.

- Уточнение каталога: сетка в 3 колонки на ширине 769–1024px выбрана намеренно; сохранять 3 колонки до 1440px включительно, 4 — выше. Это заменяет прежнее правило двух колонок до 1024px.
- Лоудер каталога — вращающаяся виниловая пластинка; при prefers-reduced-motion без вращения, с доступным текстом загрузки. Кнопки запросов блокируются и показывают загрузку. После редактирования сохраняем фильтры и положение списка; успех сообщаем неблокирующим уведомлением.

- Новое выбранное направление каталога (2026-10-25): взрослая роскошная ретро-эстетика винила и старых фотоаппаратов. За основу — карточки и расположение поиска из `a-gallery.png`, шапка с объёмным винилом и скругления фильтров из `b-compact.png` (`.impeccable/mocks/luxury-retro/`). Глубокий бордовый, светлая основа и графит; оливковый в новой концепции не используем. На десктопе остаются карточки, на мобильном — строки с главным изображением, оценкой и краткой информацией. Не превращать интерфейс в CRM.
