# Соглашения проекта Aftertaste

Эти договорённости отражают предпочтения пользователя. Применяй их при дальнейшей работе с фронтендом.

## Vue

- Vue 3, Composition API, TypeScript.
- Порядок блоков в каждом `.vue`: сначала `<template>`, затем `<script setup lang="ts">`, затем `<style>`.
- Делить интерфейс на понятные компоненты. Кнопки, поля ввода, модалки и уведомления — переиспользуемые UI-компоненты.
- Оставлять код понятным для пользователя, который учится и самостоятельно продолжает фронтенд.

## Стили

- Использовать SCSS. Все стили хранить отдельно от Vue-компонентов в `frontend/src/styles/`. Стили UI-компонентов — в `styles/ui/`, каталога — в `styles/catalog/`, корневого компонента — в `styles/App.scss`. Имя файла соответствует компоненту. Подключать через `<style scoped lang="scss" src="@/styles/ui/ComponentName.scss"></style>`. Не размещать SCSS рядом с `.vue`.
- Глобальные стили и reset — только в `frontend/src/styles/main.scss`.
- Основные цвета и семейства шрифтов — в `frontend/src/styles/_variables.scss`. Использовать семантические переменные вместо повторяющихся значений.
- Общие миксины — в `frontend/src/styles/_mixins.scss`: поля, действия модалок и адаптивность. Подключать через `@use`, не использовать устаревший Sass `@import`.
- Брейкпоинты: wide — 1920px, desktop — 1440px, laptop — 1024px, tablet — 768px, mobile — 480px.
- `respond-below(name)` включает верхнюю границу (`max-width`), `respond-above(name)` использует строго большую ширину. Не вводить произвольные брейкпоинты без необходимости.
- Стили компонента не должны случайно затрагивать соседние компоненты. Для осознанного оформления дочернего компонента использовать `:deep()`.

## Шрифты

- Пользователю нравятся необычные, выразительные шрифты.
- Выбирать бесплатные шрифты с кириллицей и разрешённым использованием в вебе.
- Текущая пара: Literata для заголовков, Onest для основного текста и UI; обе под SIL OFL.
- Семейства меняются через `$font-display` и `$font-body`. Подключение Google Fonts — в `frontend/index.html`, с системными fallback-шрифтами и `display=swap`.

## Цвета и тон интерфейса

- Текущий вариант для примерки: чистый белый фон страницы, карточек, полей и модалок вместо бежевого.

- Основной цвет — приглушённый оливково-зелёный `#626D47`: пользователь предпочёл его более яркому варианту; добавлять ярко-жёлтые акценты (основные кнопки, оценки, декоративные детали). На жёлтом фоне использовать тёмный текст.
- Тон — дружелюбный, разговорный, на «ты», чуть мягче. Без нарочитого сленга, резких формулировок и излишней поэтичности.
- Названия действий, полей и ошибки должны оставаться понятными: «Добавить запись», «Редактировать», «Не удалось сохранить».

- Дизайн — выразительный и графичный: жирная типографика, угловатые компоненты, чёткие тёмные рамки, жёсткие смещённые тени. Пользователь вернул этот вариант, сохранив актуальные цвета и белый фон. Сохранять наклоны оценок, значка `?/10` и плашки профиля. Тексты остаются спокойными и разговорными. Заголовок главной: «Сколько по десятибалльной?». 

- Обложки карточек без фото — единый оливково-зелёный фон с белыми надписями и графикой; категории различаются подписью, символом и геометрией. Не возвращать раздельные пастельные фоны категорий. Жёлтый — акцент оценки.

- Сохранять понравившуюся пользователю формулировку футера: «Можно не соглашаться с критиками».
