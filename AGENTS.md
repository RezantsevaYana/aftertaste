# Соглашения проекта Aftertaste

Эти договорённости отражают предпочтения пользователя. Применяй их при дальнейшей работе с фронтендом.

## Vue

- Vue 3, Composition API, TypeScript.
- Порядок блоков в каждом `.vue`: сначала `<template>`, затем `<script setup lang="ts">`, затем `<style>`.
- Делить интерфейс на понятные компоненты. Кнопки, поля ввода, модалки и уведомления — переиспользуемые UI-компоненты.
- Оставлять код понятным для пользователя, который учится и самостоятельно продолжает фронтенд.

## Стили

- Использовать SCSS. Все стили хранить отдельно от Vue-компонентов в `frontend/src/styles/`. Стили UI-компонентов — в `styles/ui/`, каталога — в `styles/catalog/`, корневого компонента — в `styles/app.scss`. Имена SCSS-файлов — в kebab-case, строчными буквами: `EntryCard.vue` → `entry-card.scss`. Подключать через `<style scoped lang="scss" src="@/styles/ui/component-name.scss"></style>`. Не размещать SCSS рядом с `.vue`.
- Глобальные стили и reset — только в `frontend/src/styles/main.scss`.
- Основные цвета и семейства шрифтов — в `frontend/src/styles/_variables.scss`. Использовать семантические переменные вместо повторяющихся значений.
- Общие миксины — в `frontend/src/styles/_mixins.scss`: поля, действия модалок и адаптивность. Подключать через `@use`, не использовать устаревший Sass `@import`.
- Общий контейнер страницы: ширина `90%`, максимум `1700px`, по центру. Использовать `@include container` из `_mixins.scss`; значения `$container-width` и `$container-max-width` в `_variables.scss`. Не добавлять боковые padding к контейнеру, уменьшающие полезную ширину. Правило едино для шапки и основного контента на всех экранах.
- Брейкпоинты: wide — 1920px, desktop — 1440px, laptop — 1024px, tablet — 768px, mobile — 480px.
- `respond-below(name)` включает верхнюю границу (`max-width`), `respond-above(name)` использует строго большую ширину. Не вводить произвольные брейкпоинты без необходимости.
- Стили компонента не должны случайно затрагивать соседние компоненты. Для осознанного оформления дочернего компонента использовать `:deep()`.

## Шрифты

- Пользователю нравятся необычные, выразительные шрифты.
- Выбирать бесплатные шрифты с кириллицей и разрешённым использованием в вебе.
- Утверждённая пара: Prata для заголовков, Onest для основного текста и UI; обе под SIL OFL.
- Семейства меняются через `$font-display` и `$font-body`. Подключение Google Fonts — в `frontend/index.html`, с системными fallback-шрифтами и `display=swap`.

## Цвета и тон интерфейса

- Актуальное направление по референсам пользователя: винтажная журнальная эстетика, личный альбом, наклонённые карточки и крупные заголовки с засечками. Эта договорённость заменяет прежний бело-жёлтый графичный вариант.
- Палитра: бордовый `#7D2826`, сливочный `#EFE9D7`, оливковый `#898861`, глубокий зелёный `#343723`. Бордовый — действия и оценки, сливочный — основной фон. Не возвращать ярко-жёлтый без запроса.
- Literata для выразительных заголовков и курсива, Onest для интерфейса. Тонкие рамки и мягкие тени вместо тяжёлых смещённых теней. Сохранять небольшие наклоны акцентов.
- Обложки без фото используют общую бордово-оливковую палитру и геометрию, а не отдельные пастельные цвета категорий. Пользовательские фото сохраняются.
- Тон — дружелюбный, разговорный, на «ты», без нарочитого сленга и излишней поэтичности. Действия и ошибки должны оставаться понятными.
- Заголовок главной: «Сколько по десятибалльной?».
- Сохранять формулировку футера: «Можно не соглашаться с критиками».

- Уточнение направления: более минималистичный, сдержанный вид с намёком на искусство и коллекционные издания. Больше воздуха, мягкие скругления, меньше плашек. Пользователь любит винил: использовать пластинку и конверт как акцент первого экрана, не превращать каталог в музыкальный сервис.

- Актуальная итерация каталога: минималистичный список записей, небольшой заголовок, Onest без декоративных засечек на основном экране. Без искусственных обложек, дублирования названий, большого hero и коллажа. Фото показывать только при наличии. Винил — маленький знак у логотипа. Бордовый — основное действие, оливковый — детали, светлая основа. Это заменяет прежние требования к обложкам и крупной декоративной композиции; модалки пока остаются в предыдущем оформлении.

- Последняя цветовая коррекция: пользователь отверг зеленоватый текст и сливочный фон как «милитаристские». На основном экране использовать чисто белый фон, графитовый текст, нейтральные серые линии и бордовый акцент. Не считать текущую композицию списка одобренной — пользователь недоволен результатом.

- Новая примерка палитры по двум последним референсам: Pipe `#5E1803` — действия и оценки; Sage `#788176` — маленькие детали; Rusk `#CCB999` — точечные акценты; серо-голубой `#B4C7D5` и его светлый вариант — выбор/наведение. Основа почти белая `#FAF9F6`, текст нейтральный графитовый. Не заливать страницу шалфейным или песочным.

- Последнее решение: откатить Sage/Rusk/Pipe и голубой, вернуться к винному `#7D2826` и оливковым `#898861` / `#343723` с нейтральным светлым фоном и графитовым текстом.
- Логотип в виде маленькой виниловой пластинки пользователю нравится — сохранять.
- Идея на будущее: лоудер как вращающаяся виниловая пластинка. Пока только записать; при реализации учесть prefers-reduced-motion и доступное сообщение о загрузке.
- Шрифты ещё выбираются: на странице есть временная галерея Onest, Manrope, Prata, Literata. Выбор в галерее — примерка, не окончательное утверждение.

- Шрифт утверждён: Prata (400) для заголовков и названий записей, Onest для основного текста и UI. Временная галерея удалена, выбор постоянный. Не возвращать переключатель шрифтов без запроса.

- Каталог: выше 768px сетка карточек (2 колонки до 1024, 3 до 1440, 4 выше), на 768px и меньше — строки. Под шапкой разделительная линия. Фильтры-кнопки сверху, поиск отдельной строкой под ними на всех экранах.
- BaseButton имеет ровно два варианта: primary (бордовый, целевой) и secondary (прозрачный). Единый `$radius-button: 9px`, размеры и отступы задаются только в base-button.scss, без локальных переопределений.

- Обновление карточек: при отсутствии фото показывать EntryCover с абстрактным узором. Цвета — винный и мягкий светлый оливковый `#A0A37B`, без тёмного хаки. На десктопе полноценная обложка, на планшетах и телефонах компактная миниатюра как фото. Не дублировать название на заглушке. Это заменяет прежнее правило «без искусственных обложек».

- Текущая примерка по просьбе пользователя: Onest во всём интерфейсе, заголовки и названия записей — 600 (как логотип), основной текст — 400. Это временно заменяет Prata; не считать окончательным утверждением.


## Архитектура фронтенда

- Используем собственную модульную архитектуру с идеями FSD, а не строгое следование FSD. Это заменяет прежние правила о сторах в model и сегментах ui/model страниц. Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Все сторы — в `frontend/src/stores`, с группировкой `catalog`, `auth`, `modals` по мере реализации. `stores/index.ts` создаёт Pinia. В стор выносим только необходимое общее состояние, не все переменные и не всю логику.
- Страницы: `pages/<страница>/<Имя>Page.vue`, локальные компоненты — в `components`, локальные composables — в `composables`. Другие страницы не импортируют их внутренности.
- Общие технические composables — в `shared/composables`, обычные утилиты — в `shared/lib`. Предметную логику не переносим в shared лишь потому, что она используется несколько раз.
- Общий UI группируем в `shared/ui/modals`, `shared/ui/form`, `shared/ui/buttons`. Формы записи остаются в каталоге. Оболочка, шапка и футер — в `app/layout`.
- Функции доступа к данным — в корневом `api`, например `api/catalog.ts`, в будущем `api/auth.ts`. API не импортирует сторы и UI, возвращает данные или выбрасывает ошибку. Если состоянием владеет стор, его действие выполняет запрос и обновление состояния.
- Сейчас `api/catalog.ts` использует localStorage. HTTP-клиент и интерцептор отложены до появления бэкенд-запросов. Перевод модалок на стор — отдельная будущая итерация; пока сохраняем существующее управление.
- `entities/entry` хранит типы, категории и отображение записи; не зависит от страниц, сторов и API. Shared не зависит от предметных модулей. Избегаем циклических импортов.
- Внешние импорты модулей с публичным `index.ts` идут через него; внутри используем относительные пути. Отдельный `.ts` каждому компоненту не нужен: props, emits и локальная логика остаются в script setup. Пустые папки и файлы заранее не создаём.
- SCSS остаётся в `frontend/src/styles`: оболочка — `layout`, каталог — `catalog`, общий UI — `ui`. Это дополняет прежние правила стилей. Стили корневого компонента при необходимости — `app.scss`, страницы — `catalog/catalog-page.scss`.

- Временные мок-данные и демонстрационные записи храним отдельно в `frontend/src/mocks/`, не в `api`. При подключении реального источника данных убираем соответствующие моки и их подключения.
