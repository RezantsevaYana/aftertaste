проверяем существующие карточки, включая архивные, по AT-ID и смыслу;
обновляем найденную карточку, чтобы не создавать дубликаты.
Текущие статусы ведём в Trello; здесь сохраняем правила, решения и ссылки.
Итоги сессий и конкретный следующий шаг сохраняем в [PROGRESS.md](PROGRESS.md).

Колонки:

1. Бэклог — будущие задачи и идеи.
2. Готово к работе — небольшие задачи с понятными критериями.
3. В работе — одна активная задача.
4. На ревью — реализация готова к обсуждению и проверке.
5. Готово — критерии выполнены, существенные замечания устранены.

Блокировку отмечаем в задаче с описанием препятствия. Ориентир на задачу — 1–2 часа,
крупные задачи делим; оценки уточняем по реальному темпу. Ассистент помогает вести
доску во время рабочих сессий, а разработчик самостоятельно реализует приложение.

## Шаблон задачи

- **Цель:** пользовательский или технический результат.
- **Что сделать:** конкретные границы.
- **Критерии готовности:** наблюдаемое поведение и способ проверки.
- **Что изучить:** необходимые понятия и ссылки.
- **Подсказки:** направление решения без готовой реализации.
- **Зависимости:** что требуется до начала.
- **Оценка:** предварительное время на реализацию и разбор.
- **Результат:** ссылка на изменения и вопросы для ревью.

### AT-001 — Зафиксировать стартовый стек

- Цель: понимать назначение каждого основного инструмента.
- Решение от 15 сентября 2026: Vue 3 + Vite подтверждены, Nuxt не используем;
  отдельный API на NestJS остаётся рабочей основой из README.
- Сделать: разобрать назначение выбранных инструментов и путь запроса от браузера до БД.
- Готово: выбран способ организации фронтенда и отдельного API;
  автор может объяснить путь запроса от браузера до БД.
- Изучить: SPA, HTTP, REST, различие проверки типов и валидации данных.
- Оценка: 30–60 минут.

### AT-002 — Настроить фронтенд с TypeScript

- Зависимость: AT-001.
- Сделать: создать приложение в frontend/, включить строгую проверку TS и Router;
  описать команды установки, запуска, проверки типов и сборки.
- Готово: стартовая страница открывается; проверка типов и сборка проходят.
- Изучить: tsconfig, script setup lang="ts", структура проекта.
- Оценка: 1–2 часа.

### AT-003 — Описать запись дневника в TypeScript

- Зависимость: AT-002.
- Сделать: описать пять типов контента, два состояния и поля записи;
  вывести несколько локальных примеров, включая запись без оценки.
- Готово: примеры типизируются без any; отсутствующая оценка не отображается как 0;
  неизвестный тип контента отклоняется проверкой типов.
- Изучить: union-типы, type / interface, null и optional-поля.
- Подсказка: тип number сам по себе не ограничивает число диапазоном 1–10.
- Оценка: 1–2 часа.

### AT-004 — Запустить первый endpoint NestJS

- Зависимость: AT-001.
- Сделать: создать backend/ и GET /health, описать команды запуска и проверки.
- Готово: сервер возвращает 200 и JSON; автор объясняет роль контроллера и сервиса.
- Изучить: Node.js, HTTP-метод и статус, модули, контроллеры, внедрение зависимостей.
- Оценка: 1–2 часа.

### AT-005 — Добавить начальный CI

- Зависимости: AT-002, AT-004.
- Сделать: настроить GitHub Actions для проверки типов и сборки обеих частей;
  тесты подключать по мере их появления.
- Готово: workflow выполняется на push / pull request и падает при ошибке типов.
- Изучить: workflow, job, step, lockfile, воспроизводимая установка.
- Оценка: 1–2 часа.
