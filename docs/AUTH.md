# Регистрация и вход

Регистрация проходит в два шага: email и пароль с повтором, затем обязательные
имя и фамилия и необязательный аватар. «Назад» сохраняет введённые данные;
аккаунт создаётся только после отправки второго шага. После регистрации
пользователь сразу попадает в пустую коллекцию.

Email приводится к нижнему регистру, пробелы по краям удаляются. Для пароля
в интерфейсе указано только «Минимум 8 символов», обязательных спецсимволов нет.
Технический предел — 128 символов; пробелы не обрезаются. Повторный email
возвращает 409, неверные данные входа — 401.

Имя и фамилия — по 1–100 символов, пробелы по краям удаляются. Личный кабинет
открывается через меню по аватару в шапке и позволяет изменить имя, фамилию, заменить
или удалить аватар. Email показан только для чтения. Ошибка сохранения оставляет
форму заполненной, успешное сохранение обновляет шапку и показывает уведомление.
Уход из изменённого профиля и выход из аккаунта требуют подтверждения; возврат
в коллекцию сохраняет её фильтры. Перезагрузка изменённой формы вызывает
стандартное предупреждение браузера.

Кабинет содержит «Профиль», «Пароль», «Мои категории» и «Приватность»:
боковая навигация на десктопе, вкладки до 768px. Переход между ними проверяет
несохранённые изменения. По решению от 4 ноября временно возвращена исходная
однострочная винная шапка: аватар без имени и стрелки открывает меню
«Коллекция» / «Личный кабинет» / «Выйти». На десктопе есть обычная ссылка
«Моя коллекция», на телефоне остаются логотип и аватар. Переход в коллекцию
открывает впечатления; вкладки «Впечатления» и «Планы» сохранены в каталоге.
Уход из изменённой формы сначала требует подтверждения. BaseDropdown
закрывается по Escape, клику снаружи и уходу фокуса.
У полей пароля есть доступная кнопка показа/скрытия.

Для смены пароля нужны текущий пароль, новый и его повтор. Новый пароль
должен отличаться от текущего и содержать 8–128 символов. Сервер проверяет
текущий пароль и атомарно меняет хеш, отзывая остальные сессии пользователя;
текущая сессия сохраняется. Неверный текущий пароль возвращает 401 и не меняет
пароль или сессии. Успех очищает поля и показывает уведомление, ошибка сохраняет
введённые данные. Подтверждение ухода распространяется и на эту форму.
Смена пароля также аннулирует ссылки восстановления.

Аватар — JPG, PNG или WebP до 2 МБ. Клиент вырезает квадрат по центру и уменьшает
его до 256×256; сервер проверяет формат, сигнатуру и размер. Изображение хранится
в User как data URL; SVG и удалённые URL не принимаются.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/api/auth/register` | `{ email, password, handle, firstName, lastName, avatar? }` → 201, профиль, cookie |
| POST | `/api/auth/login` | `{ email, password }` → 200, профиль, cookie |
| GET | `/api/auth/me` | 200, профиль; без действующей сессии — 401 |
| PATCH | `/api/auth/profile` | `{ firstName, lastName, avatar }` → обновлённый профиль текущего пользователя |
| POST | `/api/auth/password` | `{ currentPassword, newPassword }` → 204; остальные сессии отозваны |
| POST | `/api/auth/password-reset/request` | `{ email }` → 202 для существующего аккаунта, 404 для неизвестной почты |
| POST | `/api/auth/password-reset/check` | `{ token }` → 200 `{ valid: true }`; недействительная ссылка — 410 |
| POST | `/api/auth/password-reset` | `{ token, password }` → 204; все сессии и ссылки отозваны |
| GET | `/api/account/settings` | Категории, их настройки и `plansVisible` текущего пользователя |
| POST | `/api/account/categories` | `{ name }` → настройки с новой собственной категорией |
| PATCH | `/api/account/categories/:key` | `{ enabled?, reviewVisibility? }` → обновлённые настройки |
| PATCH | `/api/account/privacy` | `{ plansVisible }` → обновлённые настройки |
| POST | `/api/auth/logout` | 204; сессия удалена, cookie очищена |

Профиль в ответе — `{ id, email, firstName, lastName, avatar }`, без хеша пароля.
У аккаунтов, созданных до миграции профиля, имена и аватар могут быть null;
действующие сессии и записи сохраняются.

Все изменяющие запросы `/api/*` требуют заголовок `X-Aftertaste-Request: 1`.
Фронтенд добавляет его через `api/http.ts`. Вместе с ограниченным CORS это
не позволяет чужому сайту отправлять запросы от имени пользователя через браузер.
Ответы API не кешируются. `api/auth.ts` не зависит от стора; общим состоянием
аккаунта владеет `stores/auth`.

## Категории и правила приватности

`stores/preferences` загружает и сохраняет настройки через `api/account.ts`.
Все `/api/account/*` защищены AuthGuard и используют владельца из сессии.
Встроенные категории включают концерты, подкасты и лекции; подкасты и лекции
изначально выключены, остальные включены. Выключение скрывает категорию и её
записи из каталога и счётчиков, сохраняя данные в БД. При редактировании доступна
текущая категория записи, даже если она выключена.

Своя категория имеет название 1–60 символов, уникальное у владельца после
NFKC-нормализации, удаления краевых пробелов и приведения к нижнему регистру.
Запись использует `type: custom` и `customCategoryId`; сервер проверяет
принадлежность категории при создании, изменении и импорте.

Категория хранит `reviewVisibility: private | friends`; запись может наследовать
правило (`inherit`) или иметь своё `private | friends`. Исключение меняется
в форме и деталях. `plansVisible` хранит выбранную видимость планов.
Это сохранённые настройки для будущего обмена: списка друзей и API доступа
друзей ещё нет, все запросы записей по-прежнему доступны только владельцу.
Интерфейс прямо сообщает, что коллекция сейчас приватна.

Переключатели сохраняются сразу; повторные действия и уход во время сохранения
блокируются. Несохранённое название своей категории требует подтверждения ухода.

## Восстановление пароля

«Забыли пароль» открывает ввод email, подтверждение запроса, повторную отправку
и смену адреса. Ссылка открывает ввод нового пароля; есть состояния успеха
и истёкшей/использованной ссылки. Серверные ошибки авторизации и восстановления
показываются в общей `NotificationModal` с `status="error"`; введённые данные
сохраняются, после закрытия фокус возвращается в форму. Локальные ошибки
валидации остаются под полями. Превью письма в рабочем интерфейсе нет.

По решению пользователя неизвестный email получает 404 с сообщением
«Аккаунт с такой почтой не найден. Проверь адрес или зарегистрируйся.».
Для существующего аккаунта при настроенной почте возвращается 202.
Отправка асинхронная; повторное письмо одному пользователю
ограничено атомарным интервалом 60 секунд. Токен — 256 случайных бит, в БД
только SHA-256, срок 30 минут. Одноразовое погашение и смена пароля выполняются
транзакцией; повторный конкурентный запрос отклоняется. Сброс отзывает все
сессии и оставшиеся ссылки, автоматического входа нет.

Письмо содержит `#resetToken=…`: фрагмент не попадает в HTTP-запрос страницы.
App считывает и очищает URL; поддерживает изменение hash и прежний query-параметр.
Сырые токены не возвращаются в API и не записываются в журналы приложения.

## Хранение и доступ

- PostgreSQL хранит пользователя и scrypt-хеш пароля с отдельной случайной солью
  (`N=32768`, `r=8`, `p=3`). Исходный пароль не сохраняется.
- Сессия — случайный 256-битный токен в HttpOnly cookie `aftertaste_session`,
  SameSite=Lax, срок 30 дней. В БД хранится только SHA-256 токена.
- Сессия переживает перезапуск API. Выход удаляет её на сервере; прежняя cookie
  больше не даёт доступ. Истёкшие сессии отклоняются и очищаются при создании новых.
- Все операции каталога защищены AuthGuard. `userId` берётся из сессии, а не из
  тела запроса. Чужие записи не попадают в список; изменение и удаление возвращают
  404. Изменить владельца через данные записи нельзя.
- При первой загрузке приложение проверяет сессию. Пока сервер недоступен,
  показывает ошибку с повторной попыткой. Без сессии открывает форму входа.
- Прежняя анонимная коллекция удалена миграцией `20261102000000_auth` по явному
  запросу владельца. Автоматическое заполнение демоданными и перенос из JSON или
  localStorage отключены. Новые аккаунты пустые.

## Локальный запуск и HTTPS

`docker compose up -d --build` собирает приложение и применяет миграции.
Локальный адрес — http://localhost:8080. На локальном HTTP `COOKIE_SECURE=false`.
При размещении через HTTPS обязательно установить `COOKIE_SECURE=true` и
`FRONTEND_ORIGIN=https://адрес-сайта`. Фронтенд и API предполагаются на одном
origin; Vite использует прокси `/api`, nginx — прокси на backend.

`TRUST_PROXY=true` в Compose включает доверие ровно одному reverse proxy.
Nginx заменяет `X-Forwarded-For` реальным адресом клиента. Backend не публикуется
наружу; при прямом запуске оставлять `TRUST_PROXY` выключенным. Не включать
доверие прокси, если API доступен клиентам напрямую.

### Почта

Compose по умолчанию отправляет письма в локальный Mailpit: просмотр —
http://localhost:8026, SMTP с хоста — `127.0.0.1:1026`, из backend-контейнера —
`mailpit:1025`. Это локальный приёмник, письма во внешний почтовый ящик
он в текущей конфигурации не доставляет. Порты меняются через
`MAILPIT_HTTP_PORT` / `MAILPIT_SMTP_PORT`; настройка контейнера описана
в [документации Mailpit](https://mailpit.axllent.org/docs/install/docker/).

Для реального почтового ящика нужен SMTP-провайдер: задать `SMTP_HOST`,
`SMTP_PORT`, `SMTP_FROM`, при необходимости `SMTP_USER` и `SMTP_PASSWORD`.
`SMTP_SECURE=true` включает TLS сразу (обычно порт 465);
для STARTTLS (обычно 587) — `SMTP_SECURE=false`, `SMTP_REQUIRE_TLS=true`.
Параметры транспорта — в [документации Nodemailer](https://nodemailer.com/smtp).
`PUBLIC_APP_URL` задаёт адрес приложения в письме (в Compose по умолчанию
`http://localhost:8080`); для размещения указать публичный HTTPS-адрес.
Переменные Compose задаются в окружении или корневом `.env`.

Без `SMTP_HOST` или `SMTP_FROM` запрос восстановления существующего аккаунта
возвращает 503. Неизвестная почта возвращает 404 до проверки SMTP. Ошибки доставки журналируются без email и токена. Постоянной очереди
заданий пока нет: перезапуск backend может прервать асинхронную отправку;
если письмо не пришло, повторить запрос после минутного интервала.

## Проверки и границы текущей версии

`npm test` и `npm run lint` в backend; `npm run build` в обеих папках.
Тесты проверяют обязательность имени и фамилии, формат/размер аватара,
ограничение обновляемых полей профиля, соль/пароль, нормализацию email, отказ при некорректных данных,
одинаковую ошибку входа для неизвестного email и неправильного пароля, хранение
хеша токена, истечение сессии и область доступа к каталогу. HTTP-тесты также
проверяют обязательный защитный заголовок, запрет кеширования и независимый
лимит попыток для разных IP за доверенным прокси.
Дополнительно проверены реальный API с двумя аккаунтами и браузерные сценарии
регистрации, входа, выхода и восстановления сессии на десктопе и телефоне.
Проверки смены пароля покрывают неверный текущий пароль, ограничения нового,
сохранение текущей сессии и отзыв остальных. В живом API также проверены
редактирование профиля, отказ входа со старым паролем и вход с новым.

Вход, регистрация, смена пароля и endpoints восстановления ограничены
20 попытками с одного IP за 15 минут. Счётчик пока
в памяти одного процесса: для нескольких экземпляров API нужен общий лимитер.
Дополнительно в живом API проверены изоляция настроек двух аккаунтов,
принадлежность своих категорий, сохранность скрытых записей, исключения
приватности, доставка в Mailpit, конкурентный сброс (один 204, другой 410),
отзыв всех сессий и вход с новым паролем.
Подтверждения email, доступа друзей и отдельной команды завершения всех сессий
пока нет. История визуальных решений — в [PROTOTYPES.md](PROTOTYPES.md).

### Ник при регистрации

Ник обязателен на втором шаге регистрации вместе с именем и фамилией.
Клиент и сервер принимают 3–50 латинских букв, цифр, точек, дефисов и
подчёркиваний; первый символ — буква или цифра. Сервер убирает крайние
пробелы и приводит ник к нижнему регистру. Ограничение `User.handle @unique`
проверяет занятость и защищает от одновременной регистрации одинаковых ников.
При конфликте `/auth/register` возвращает 409 с `field: "handle"` или
`field: "email"`; конфликт ника показывается под полем без сброса профиля.
Те же правила и ошибка поля используются при изменении ника в ЛК.

Прежние аккаунты могли получить технический ник через Prisma `cuid()` по
умолчанию. Их ники автоматически не меняются; пользователь может выбрать
свой в профиле. Новая регистрация через API всегда требует выбранный ник.
