# aftertaste

Личный дневник книг, фильмов, сериалов, спектаклей и музыкальных альбомов.
Помогает сохранять впечатления, вспоминать оценки и планировать, что посмотреть,
прочитать или послушать. В следующих версиях — обмен с друзьями и совместные списки.

## Текущие прототипы

[Ссылки, запуск и сохранённая версия аккаунта](docs/PROTOTYPES.md) — точка продолжения
для следующей сессии. Последняя фиксация: 2 ноября 2026, компактные мобильные экраны.

## Цели проекта

- Заменить личные списки в заметках удобным интерфейсом на компьютере и телефоне.
- Углубить TypeScript и навыки разработки на Vue.
- Самостоятельно освоить сервер, HTTP API, SQL, базы данных, тестирование и CI/CD.

Разработка — учебная, ориентировочно 3–4 часа в неделю. Автор самостоятельно
реализует задачи; ассистент помогает с продуктом, объяснениями, декомпозицией и ревью.

## MVP: личный дневник

### Основные сценарии

1. Войти в свой аккаунт и открыть дневник.
2. Вручную добавить произведение в планы или сразу в завершённое.
3. Указать оценку, написать рецензию и сохранить дату завершения.
4. Найти запись, вспомнить впечатление, изменить или удалить запись.

### Возможности

- Личный аккаунт: регистрация, вход, выход; доступ только к своим данным.
- Типы контента: книга, фильм, сериал, спектакль, музыкальный альбом.
- Обязательные поля записи: название, тип контента, состояние.
- Состояния: «Хочу» и «Завершено».
- Необязательные поля: оценка, рецензия, дата просмотра / прочтения / прослушивания.
- Десятибалльная шкала. Рабочее допущение: целые числа от 1 до 10;
  отсутствие оценки хранится отдельно, а не как 0.
- Список записей, поиск по названию, фильтры по типу и состоянию.
- Редактирование и удаление своих записей.
- Адаптивный интерфейс, состояния загрузки, ошибок и пустого списка.

### Критерий готовности MVP

Развёрнутым приложением можно пользоваться с телефона: войти, добавить запись,
поставить оценку и написать рецензию, затем найти её после перезагрузки страницы.
Данные сохраняются в БД; второй пользователь не может прочитать или изменить чужие
записи через интерфейс или прямые запросы к API. Проверки типов, значимых сценариев
и сборки проходят в CI; процедура деплоя описана.

### За пределами MVP

- Друзья, выдача доступа к рецензиям и совместные списки.
- Семейная статистика и сравнение оценок.
- Внешние каталоги, автоматический поиск обложек, импорт заметок.
- Повторные просмотры с отдельными впечатлениями, сезоны и прогресс чтения.
- Установка как PWA, офлайн-режим и синхронизация.

## Следующие версии

### Доступ

| Пользователь | Доступ |
| --- | --- |
| Владелец | Все свои записи; чтение и изменение |
| Друг | Список контента и оценки |
| Друг с дополнительным разрешением | Также чтение рецензий |
| Посторонний | Нет доступа |

Владелец выдаёт и отзывает разрешение на чтение рецензий для конкретного друга.
Рабочее допущение: разрешение распространяется на все рецензии владельца;
удаление из друзей также прекращает доступ. Детали подтвердим перед реализацией.
Сервер проверяет права и не возвращает закрытые поля в ответах API.

### Совместные списки

- Общий набор планов с индивидуальными отметками о завершении.
- Планы на совместный просмотр / прочтение / прослушивание.

Оценки и рецензии всегда личные. Одно произведение может быть связано с записями
разных пользователей. Детальную схему БД и правила сопоставления вручную добавленных
произведений спроектируем отдельной задачей. Социальные функции заранее не реализуем.

## Стек

Для фронтенда выбран Vue 3 + Vite; Nuxt не используем. Остальной стек ниже —
рабочая основа для учебных целей проекта. Фронтенд находится в `frontend/`;
для него используем Node.js 24 (версия указана в `.nvmrc`).

| Область | Технологии | Назначение |
| --- | --- | --- |
| Фронтенд | Vue 3, Composition API, Vite | Клиентское приложение |
| Язык | TypeScript, strict | Типизация фронтенда и сервера |
| Навигация | Vue Router | Страницы приложения |
| Общее состояние | Pinia | Общее клиентское состояние; подключена при старте проекта |
| Стили | CSS / SCSS, scoped-стили | Адаптивная вёрстка; вариант уточним с дизайном |
| Бэкенд | Node.js, NestJS | Отдельное серверное приложение |
| API | REST, JSON, OpenAPI / Swagger | Контракт, документация и проверка запросов |
| Проверка входных данных | ValidationPipe, class-validator | Валидация на сервере во время выполнения |
| База данных | PostgreSQL | Данные, связи и ограничения |
| Доступ к БД | Prisma и миграции | Типизированные запросы и изменения схемы |
| Тесты фронтенда | Vitest | Значимая логика и поведение компонентов |
| Тесты сервера | Vitest, Supertest | API, бизнес-правила и права доступа |
| Сквозные тесты, позже | Playwright | Ключевые сценарии в браузере |
| Локальная инфраструктура | Docker Compose | PostgreSQL, API, фронтенд, Adminer |
| CI/CD | GitHub Actions | Проверки, сборка, затем деплой |

Один репозиторий: фронтенд в `frontend/`, сервер NestJS в `backend/`;
один сервер и одна БД.
Механизм аутентификации, площадка размещения и бюджет — отдельные решения до
реализации входа и публичного размещения. SQL изучаем также вручную: ключи,
ограничения, SELECT, JOIN, агрегаты, транзакции и индексы по мере появления задач.

### Почему Vue + Vite, а не Nuxt

Nuxt построен на Vue и поддерживает серверный, клиентский и гибридный рендеринг.
Он также позволяет писать серверные API через Nitro. Поэтому Nuxt — полноценный
альтернативный вариант, включая Nuxt с отдельным NestJS API.

Для текущего MVP подтверждён Vue 3 + Vite (15 сентября 2026): дневник находится за входом, публичных
индексируемых страниц нет, а отдельный NestJS помогает целенаправленно изучать
серверную архитектуру. Это уменьшает число одновременно осваиваемых инструментов.

Вернуться к Nuxt стоит при отдельной учебной цели освоить его или при появлении
публичных страниц произведений и рецензий, которым нужны SEO и серверный рендеринг.
PWA само по себе не требует Nuxt. Переход на Nuxt будет отдельной работой.

Источники: [режимы рендеринга Nuxt](https://nuxt.com/docs/4.x/guide/concepts/rendering),
[сервер Nuxt](https://nuxt.com/docs/4.x/getting-started/server),
[NestJS](https://docs.nestjs.com/),
[TypeScript во Vue](https://vuejs.org/guide/typescript/overview).

## Локальный запуск приложения

Сначала установи зависимости фронтенда и бэкенда:

```sh
nvm use
cd frontend
npm install
cd ../backend
npm install
```

Для запуска обоих серверов одной командой перейди в `frontend` и выполни:

```sh
cd frontend
npm run dev
```

Команда поднимает Vite и NestJS; адрес сайта Vite покажет в терминале (обычно
`http://localhost:5173`). Остановка через `Ctrl+C` завершает оба процесса.
Нужен Node.js версии 22.18+ или 24.12+.

Только фронтенд или backend можно запустить командами `npm run dev:frontend` и
`npm run dev:backend` из папки `frontend`. `npm run type-check` проверяет типы,
`npm run build` собирает фронтенд.

Backend отдельно запускается так:

```sh
cd backend
npm run start:dev
```

Сведения о проверках: [docs/BACKEND_SETUP.md](docs/BACKEND_SETUP.md).

## Запуск через Docker

Если установлен Docker Desktop, из корня проекта выполни:

```sh
docker compose up --build
```

После сборки приложение будет доступно на http://localhost:8080, просмотр
PostgreSQL в Adminer — на http://localhost:8081. Остановка — `Ctrl+C`; для
остановки и удаления контейнеров выполни `docker compose down`.
Записи хранятся в PostgreSQL в постоянном Docker volume `aftertaste-db` и
переживают перезапуск контейнеров. Adminer: сервер `database`, база `aftertaste`,
логин `aftertaste`, пароль `aftertaste-local`. Предыдущий JSON-файл остаётся в
`aftertaste-data` как резервная копия. Чтобы удалить базу и резервную копию,
используй `docker compose down -v`.
