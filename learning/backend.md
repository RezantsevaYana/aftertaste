# Backend Aftertaste: NestJS, API и PostgreSQL

Краткое введение в backend на примере текущего проекта. Фронтенд написан на Vue,
сервер — на NestJS и TypeScript. NestJS принимает HTTP-запросы, Prisma переводит
операции с данными в запросы к PostgreSQL.

## Как проходит запрос

```text
Vue в браузере
  → HTTP-запрос /api/entries
  → NestJS controller: маршрут и проверка входных данных
  → NestJS service: сценарий работы с записью
  → Prisma Client
  → PostgreSQL
  → JSON-ответ браузеру
```

Фронтенд не подключается к базе напрямую. Он общается только с API. Сервер
контролирует входящие данные и решает, что читать или менять в базе.

## Основные понятия на коде проекта

### NestJS-модуль

Модуль объединяет связанные части приложения. В `AppModule` подключены
`CatalogController`, `CatalogService` и `PrismaModule`. Nest создаёт нужные
классы и связывает их зависимости.

### Controller

Контроллер связывает HTTP-маршрут с методом приложения. Например,
`@Controller('api/entries')` задаёт общий адрес каталога, а `@Get()` и `@Post()`
задают действия для конкретных HTTP-методов.

| Запрос | Что делает |
| --- | --- |
| `GET /api/entries` | Возвращает записи каталога |
| `POST /api/entries` | Создаёт запись |
| `POST /api/entries/import` | Однократно переносит записи, только если база пустая |
| `PUT /api/entries/:id` | Заменяет запись с указанным id |
| `DELETE /api/entries/:id` | Удаляет запись |

`@Body()` достаёт JSON из тела запроса, `@Param('id')` — id из адреса.
Контроллер проверяет запись функцией `validateEntry` и передаёт работу сервису.

### Service

Сервис содержит действия с каталогом. `CatalogService` читает записи из базы,
создаёт, редактирует и удаляет их. Он переводит ошибки Prisma в HTTP-ошибки:
например, отсутствующая запись становится `404 Not Found`.

### Dependency Injection

Nest передаёт зависимость через конструктор:

```ts
constructor(private readonly prisma: PrismaService) {}
```

Класс не создаёт Prisma вручную — Nest находит зарегистрированный `PrismaService`
и передаёт его. Так проще заменять зависимости и проверять код отдельно.

### Prisma и схема базы

Prisma — ORM: инструмент, который связывает TypeScript-модели и запросы к базе.
В `backend/prisma/schema.prisma` описана таблица `Entry`, её поля и перечисления
для типов записей и жанров спектаклей. Из схемы генерируется Prisma Client с
типизированными методами, например `prisma.entry.findMany()`.

Миграция — версия изменений схемы базы. SQL-файл в
`backend/prisma/migrations/` создаёт таблицы и индексы. При запуске контейнера
команда `prisma migrate deploy` применяет ещё не применённые миграции.

`PrismaService` наследуется от `PrismaClient`, подключается при старте NestJS и
закрывает соединение при завершении приложения.

### Перенос старых данных

При старте `CatalogService` проверяет, пуста ли PostgreSQL. Если да, он ищет
старый файл `entries.json` и копирует записи в базу. Файл остаётся резервной
копией. Endpoint `/api/entries/import` похожим образом переносит данные браузера,
но ничего не перезаписывает, если каталог в базе уже есть.

## Пример HTTP-запроса

Получить каталог можно так:

```http
GET /api/entries
```

Ответ — JSON-массив записей:

```json
[
  {
    "id": "entry-123",
    "type": "book",
    "title": "Нормальные люди",
    "rating": 9,
    "review": "Сильно запомнилась.",
    "month": "2026-09"
  }
]
```

## Что уже есть и чего пока нет

- Есть API каталога, проверка данных на сервере, PostgreSQL, Prisma и миграция.
- В Docker Compose база сохраняется в отдельном volume. Adminer на
  `http://localhost:8081` позволяет смотреть таблицы и строки базы.
- Сейчас есть одна предметная таблица `Entry` и служебная таблица
  `_prisma_migrations`.
- Нет регистрации, входа и разделения записей по пользователям: текущий каталог
  общий для этого экземпляра приложения.
- Нет пагинации и поиска на сервере: фронтенд загружает весь каталог и фильтрует
  его в браузере.
- Валидация написана вручную в `validateEntry`; отдельные DTO-классы и
  `class-validator` пока не подключены.

## Вопросы для собеседования

### Чем Controller отличается от Service?

Controller принимает HTTP-запрос, выбирает маршрут, получает параметры и
возвращает ответ. Service выполняет сценарий приложения и обращается к данным.
Так HTTP-детали не смешиваются с логикой каталога.

### Что такое Dependency Injection?

Это способ передать классу нужные зависимости извне. В NestJS контейнер создаёт
провайдеры и передаёт их, например, в конструктор `CatalogService`. Код меньше
зависит от ручного создания конкретных объектов.

### Что такое REST API?

Это способ описывать операции над ресурсами через HTTP. В Aftertaste ресурс —
запись каталога: `GET` читает, `POST` создаёт, `PUT` обновляет, `DELETE` удаляет.

### Чем `PUT` отличается от `POST`?

`POST` обычно создаёт ресурс, а `PUT` заменяет ресурс по известному адресу.
В Aftertaste адрес обновления включает id записи: `PUT /api/entries/:id`.

### Что делает ORM и зачем в проекте Prisma?

ORM связывает модели кода с таблицами базы. Prisma генерирует типизированный
клиент, поэтому сервер может вызвать `prisma.entry.findMany()` вместо ручного
составления SQL для каждого действия.

### Что такое миграция базы данных?

Миграция — записанное изменение структуры базы, например создание таблицы или
индекса. Миграции позволяют одинаково обновлять схему у разработчиков и на
сервере и хранить историю этих изменений в Git.

### Где должна выполняться валидация: во Vue или на сервере?

На обоих уровнях, но с разной целью. Vue помогает человеку быстро исправить
форму. Сервер обязан проверить данные независимо от фронтенда, потому что API
можно вызвать напрямую и отправить некорректный JSON.

### Что означают коды `400`, `404`, `409` и `204` в этом API?

- `400 Bad Request` — тело запроса не прошло проверку.
- `404 Not Found` — запись с таким id не найдена.
- `409 Conflict` — создаваемый id уже занят.
- `204 No Content` — удаление прошло успешно, ответа с телом нет.

### Как сервер понимает, какую запись обновить или удалить?

Клиент отправляет id в URL, например `DELETE /api/entries/entry-123`. NestJS
достаёт его через `@Param('id')`, а Prisma использует как первичный ключ таблицы.

### Как данные переживают перезапуск Docker?

Контейнер PostgreSQL пишет файлы базы в именованный Docker volume. Перезапуск или
пересборка контейнера не удаляют volume. Команда `docker compose down -v` удалит
его, поэтому её нельзя использовать, если данные нужно сохранить.
