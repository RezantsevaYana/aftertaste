# CSS и SCSS

## Вложенность и организация стилей

SCSS — синтаксис Sass: он расширяет CSS переменными, миксинами и другими возможностями. Сборщик компилирует SCSS в CSS, который читает браузер.

В проекте держим базовые стили, состояния и адаптив элемента в одном блоке. Дочерние элементы располагаем внутри блока компонента:

```scss
.entry-card {
  padding: 18px;

  @include respond-below('tablet') {
    padding: 14px;
  }

  .entry-photo {
    width: 100%;
    aspect-ratio: 3 / 2;

    @include respond-below('tablet') {
      width: 70px;
      height: 94px;
      aspect-ratio: auto;
    }
  }

  &:hover {
    background: $color-soft;
  }
}
```

Это упрощённый пример: все правила изображения находятся рядом. `.entry-card { .entry-photo { ... } }` создаёт селектор `.entry-card .entry-photo`, а `&:hover` — `.entry-card:hover`.

Вложенность увеличивает специфичность селектора, поэтому не стоит воспроизводить в SCSS всю глубину HTML. Обычно достаточно 2–3 уровней. Она также не заменяет Vue `scoped`: это разные способы ограничения стилей. Для намеренного оформления внутренних элементов дочернего компонента используется `:deep()`.

`&__photo` внутри `.card` создаёт класс `.card__photo`, **не** селектор потомка `.card .card__photo`. Если нужна привязка к родителю, пишем дочерний класс целиком.

У телепортированного меню другой родитель в DOM. Его стили нельзя вкладывать в селектор поля, из которого оно открылось: нужен отдельный блок меню.

## Что такое respond-below

`respond-below` — наш миксин из `frontend/src/styles/_mixins.scss`, а не встроенное свойство CSS. Миксин — переиспользуемый фрагмент SCSS. `@include` вызывает его, а `@content` подставляет переданный блок правил.

```scss
.entry-grid {
  display: grid;

  @include respond-below('tablet') {
    display: flex;
  }
}
```

После компиляции:

```css
.entry-grid {
  display: grid;
}

@media (max-width: 768px) {
  .entry-grid {
    display: flex;
  }
}
```

В исходном SCSS класс записан один раз. Повторение в сгенерированном CSS нормально: этот файл редактировать не нужно.

Имена и размеры берутся из `$breakpoints` в `_variables.scss`:

| Имя | Ширина |
| --- | --- |
| mobile | 480px |
| tablet | 768px |
| laptop | 1024px |
| desktop | 1440px |
| wide | 1920px |

`respond-below('tablet')` включает 768px и всё, что меньше. `respond-above('tablet')` действует строго выше 768px. Это условия ширины области просмотра, а не проверка устройства.

На ширине 400px одновременно выполняются `respond-below('tablet')` и `respond-below('mobile')`. При одинаковой специфичности более позднее объявление одного свойства перекрывает более раннее. Поэтому при перегруппировке стилей важно сохранять порядок перекрывающихся правил и учитывать сокращённые свойства вроде `padding`.

## Вопросы для собеседования

**Чем SCSS отличается от CSS?** SCSS обрабатывает препроцессор Sass. Браузер получает итоговый CSS; конструкции Sass `@mixin` и `@include` он не выполняет. Современный CSS тоже поддерживает вложенность, но это не делает его синтаксисом Sass.

**Что делает медиазапрос?** Условно применяет правила, например в зависимости от ширины области просмотра или предпочтения уменьшенной анимации.

**Зачем нужны миксины адаптива?** Они позволяют использовать единые именованные границы, проверять их существование и не повторять числовые значения в разных компонентах.

**Почему слишком глубокая вложенность неудобна?** Она повышает специфичность, привязывает стили к структуре DOM и затрудняет переопределения.
